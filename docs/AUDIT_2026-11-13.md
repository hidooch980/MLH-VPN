# Molla VPN — Repository Audit (2026-11-13)

## Scope and method

Reviewed the GitHub repository `hidooch980/Voice-Ai`, the development branch
`bootstrap/molla-vpn-foundation`, its merge into `main`, backend API/auth/account/device/peer
code, Flutter shell, Ansible WireGuard role, documentation and GitHub Actions configuration.
This is a source/configuration review, not a penetration test, provider review or live VPN test.

## Executive result

**Status: merged development foundation; not production-ready and not a usable VPN service.**

The repository now contains a FastAPI scaffold, password/token primitives, persistent SQLite
account/session/subscription storage, an account-scoped device registry, a public-key-only
WireGuard peer registry, a Flutter placeholder UI and a guarded Ansible server template.
The reviewed foundation was merged into `main` at commit
`fb97dbb0686535d0cc81929639416d804dc65919`. Subsequent security-automation changes are on
`bootstrap/molla-vpn-foundation` and require their own review/merge.

No live VPN node, native tunnel adapter, client profile issuance, billing integration or
production connection has been verified.

## Repository and governance

- Repository: `hidooch980/Voice-Ai` (public).
- The initial foundation is present on `main`; new security automation is being developed on

## Backend findings

- FastAPI currently exposes only `GET /health` and read-only `GET /api/v1/protocols`.
- Protocol descriptors remain planned/disabled and return no endpoint or private-key material.
- Password hashes use scrypt; access-token primitives use HMAC-SHA256 with issuer, audience,
  type, issue-time and expiry checks.
- SQLite account/session/subscription persistence exists. Sessions are revocable; account
  suspension revokes sessions; active subscription checks require timezone-aware expiry.
- Account and device database files are restricted to mode 0600 on supported POSIX systems.
- Account-scoped device enrollment enforces account status, subscription status and device
  limits within a SQLite write transaction, allocates IPv4 addresses atomically, and stores
  client public keys only.
- Public registration/login/session HTTP routes are not implemented. This avoids exposing
  unverified accounts without persistent rate limiting, verified ownership, recovery, MFA,
  audit and deployment-secret controls.
- There is no production secret manager integration, key rotation workflow, MFA, admin
  bootstrap or persistent login throttling.

## Device and peer management

- Device and peer registries validate canonical WireGuard public keys and prevent duplicate
  key/device/IP assignments.
- Device enrollment is account-owned and subscription-gated.
- Registry revocation is database state only. No reconciler applies peer changes to a running
  WireGuard interface; therefore revocation does not yet terminate a live tunnel.
- No authenticated device-enrollment API or short-lived client configuration issuance exists.

## Client findings

- Flutter is a UI shell only; the connect action is intentionally disabled.
- Native Android/iOS/Windows/macOS runner projects and VPN tunnel adapters are not present.
- No real DNS, IPv4/IPv6 leak, kill-switch, reconnect, sleep/wake, network-handoff, throughput,
  battery or MTU integration test has been performed.
- iOS/macOS require macOS/Xcode build infrastructure; Windows requires a Windows build host.

## Infrastructure findings

- Ansible is a provisioning template and has not been run against a real server.
- The role generates the server private key on the target, marks secret-bearing tasks
  `no_log`, enforces restrictive permissions, and refuses to overwrite unmanaged WireGuard
  configuration unless explicitly overridden.
- Provider firewall integration is absent; UFW/nftables compatibility is unverified; IPv6
  forwarding/leak policy and DNS are not configured.
- No client peers are provisioned. A WireGuard interface with no authorized client peer is
  not a customer-ready VPN.
- Hosting provider, region, budget and expected concurrency have not been selected.

## Remaining release gates

1. Complete verified account lifecycle, persistent login throttling, admin bootstrap,
   authenticated/revocable sessions, audit events and secure runtime secret configuration.
2. Expose authenticated device APIs and enforce account ownership, subscription status and
   device limits for every operation.
3. Implement one-time device enrollment and short-lived configuration issuance.
4. Reconcile peer add/remove operations with real WireGuard nodes and prove revocation stops
   traffic.
5. Implement Android native VPN service and WireGuard adapter; then independently implement
   and test iOS, Windows and macOS adapters.
6. Select and approve a hosting provider/region/budget, then deploy hardened nodes with
   firewall, IPv6 and DNS policies and a tested rollback.
7. Pass end-to-end traffic, DNS, IPv4/IPv6 leak, kill-switch, reconnect, roaming, MTU, load and
   failure-recovery tests on every advertised platform.
8. Add signed/reproducible releases, SBOM/dependency review, privacy/legal review, billing,
   monitoring, backup/restore and support operations.
9. Enable branch protection/required checks, select a repository license and review public
   repository secret-scanning settings before commercial release.

## Verdict

The repository foundation is merged and its main application CI has begun validating the
merged code. Security automation has been added but its first results remain pending. The
remaining work is substantial product and operational engineering, not cosmetic cleanup.
Keep all protocol entries disabled and the client connection action unavailable until
end-to-end evidence proves a real VPN tunnel and its security controls.

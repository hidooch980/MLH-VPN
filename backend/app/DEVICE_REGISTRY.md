# Account-scoped device registry

The internal SQLite device registry shares the account database and transaction boundary.

- Device enrollment requires an active account and active/trial subscription.
- The subscription's maximum-device entitlement is checked inside a SQLite `BEGIN IMMEDIATE` transaction.
- A unique device ID is generated by the service; clients cannot choose another account's device ID.
- Supported platform identifiers are `android`, `ios`, `windows` and `macos`.
- The client submits a canonical WireGuard public key only. Client private keys are not accepted.
- IPv4 addresses are allocated from the configured pool while reserving the server address.
- Active IP uniqueness is enforced by a partial unique index; revoking a device releases its address while retaining its audit record.
- Revocation is owner-scoped and idempotent state is retained.

## Not yet connected to a live VPN node

This is a database/domain component, not an HTTP endpoint. It does not apply a peer to WireGuard, produce a client profile, or stop an already active tunnel. Authenticated API routes and a privileged, audited node-reconciliation adapter must be implemented before this component can provision production access.
